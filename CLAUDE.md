# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Fabula (public name, ruled 2026-08-27; developed under the codename TOC Fable, which the dated notes in `docs/` keep as historical record) — a pure client-side web app that renders a documentation table of contents as cards on an infinite canvas, so its information architecture can be seen whole, restructured by dragging, and written back to the source file losslessly. It is an upstream IA **planning** tool (audience: technical writers, docs managers, content strategists), not a help-authoring tool.

No server, no accounts, no analytics; sessions persist to localStorage. License: AGPL-3.0.

**Product truth lives in [PRODUCT.md](PRODUCT.md)** — read it before any product or design decision. The two facts most easily got wrong from the code alone: this is **a personal tool, open-sourced under copyleft so it cannot be sold — not a commercial product**, so don't design pricing, growth or upsell into it; and there is a **third audience who never opens the app** (reviewers shown a structure they don't know), which is why "legible to a stranger" is a product principle. Where value comes from, stated as capability rather than market position: workflow depth — round-trip fidelity, validation, review, exports — rather than the LLM call.

## Commands

`pnpm install`, then:

- `pnpm dev` — Vite dev server at http://localhost:5173 (`pnpm build` / `pnpm preview` for the production bundle)
- `pnpm check` — TypeScript (`tsc --noEmit`)
- `pnpm lint` / `pnpm format:check` — ESLint / Prettier (`pnpm format` writes)
- `pnpm test` — vitest (unit + property + conformance); one file: `pnpm test src/ai/__tests__/parse.test.ts`; one case: append `-t 'name'`; `pnpm test:watch` to iterate
- `pnpm e2e` — Playwright flows; one spec: `pnpm e2e e2e/flow8-ai-reorganize.spec.ts`. Needs `pnpm exec playwright install chromium` once per machine
- `pnpm fixpoint` — parse→serialize fixpoint check over the samples

CI (`.github/workflows/ci.yml`) runs check, lint, format:check, test, build, e2e — all must pass.

Test-harness facts that shape what is testable:

- **Vitest runs in a `node` environment, not jsdom** (`vite.config.ts`), and that is load-bearing: the store is DOM-free by design and layout never reads the DOM — cards report their sizes into `measuredHeights`. Logic that reaches for `window` can't be unit-tested and falls through to e2e; keep it out of the store and layout.
- **`pnpm e2e` builds and serves the production bundle** on port 4173 with `reuseExistingServer: false` — a full `pnpm build` every run, deliberately, so a stale preview server can't make failures lie. Specs target `data-testid` / `data-card-variant` attributes, and every flow ends with `assertClean()` from `e2e/helpers.ts`: **zero console errors tolerated**.
- **Property tests use a fixed fast-check seed in CI and a free seed locally** (`src/test/setup.ts`). A local failure may not reproduce in CI and vice versa — reproduce with the seed the failing run printed rather than assuming flakiness. fast-check appends `{ seed, path, endOnFailure }` to every property failure, and `FC_SEED=<n> pnpm test <file>` replays it (overriding CI's fixed seed too), so a red run is reproduced by pasting one number. A **timeout** carries no seed and is not this class. **This dev machine runs at load average 15–20 as its NORMAL state** (a game stream is always open), so "re-run it on a quiet machine" is advice nobody here can take: heavy fast-check properties and corpus-parse tests exceed vitest's 5s default under whole-suite parallelism while passing in isolation every time. **On a timeout, STOP AND REPORT — do not diagnose it and do not add a budget.** Say which test timed out and hand it back; the author closes GeForce NOW and asks for a rerun. That rerun is a real CONTROL GROUP, which neither re-diagnosing nor budgeting ever was: a test that passes on the cleared machine was contention, and one that still fails is a genuine finding that a budget would have buried. Existing budgets stay (the HEAVY, NOT SLOW comments record measured actuals of 52–940ms — heavy, never slow), but reach for a new one only after a cleared-machine run says the test really is that expensive. CI and real users have neither the load nor the constraint, so a timeout here is never evidence that product code needs optimising.

- **The paint check's failure mode is systematically FALSE-NEGATIVE.** The instrument is adversarial to the product — it drives real pointers at real pixels — so its own defects arrive dressed as product findings. Six in one build (docs/16), every one reporting working code as broken: a centre-grab that rubber-banded, a stale viewport, a hit-test on a non-participant, 30s absence waits, a strict-mode locator error swallowed as "absent", and a log naming the row the probe had skipped. **Corollary: on a harness FAIL, suspect the probe before opening product code** — the base rate says it is the probe, and the expensive direction is spending a session inside code that was fine.
  - **Defects land in the instrument's DEFAULT BRANCH, and the direction differs by instrument kind.** A probe's default is "I saw nothing", so probes FALSE-BREAK — they report working code as broken. An oracle's default is "that looks right", so oracles FALSE-PASS — they agree with a straw man and certify nothing. Both receipts come from the docs/16 step-8 receipt in one sitting: whole files passed as patch originals made every hunk claim the body was deleted (probe, false-break), and `applyChanges` as the expected-bytes oracle ignores `region` entirely, so it would have blessed any splice at all (oracle, false-pass). **Where two shipped implementations of one job exist, DIFFERENTIAL TESTING between them is the oracle of record** — the patch writer against the File System Access writer, not either against a simulation.
  - **Three verdicts, never two: MEASURED-PRESENT / MEASURED-ABSENT / INDETERMINATE.** A probe exception — a locator error, strict-mode ambiguity, a null from a non-participant — is INDETERMINATE and fails the RUN as a harness defect. It must never collapse into ABSENT, because absent is a legitimate ANSWER here (an unmeasured corpus has no inbound line) and conflating the two makes a broken instrument indistinguishable from a true negative. Same shape as the oracle-reporting rule: the instrument reports its own HEALTH separately from its MEASUREMENT.
  - **An unmet PRECONDITION is not a harness defect — it is a third failure kind with its own rung.** Exit 1: a claim did not hold (read the notes). Exit 2: a probe could not measure (fix the instrument). Exit 3: the run could not start (meet the precondition). Reporting the third as the second sends a reader into an instrument that is fine — receipt: receipt-stream's three "INDETERMINATE (0ms)" probes (2026-08-20) were a dev server that wasn't running, cost a chartered arc, and were diagnosed off a duration that was a literal. Browser-driving scripts preflight the app before launching anything, in paint-check's shape.
  - **An error-path test asserts the handler's DISTINCTIVE ARTIFACT, not the exit polarity.** An exit code can be produced by the wrong path entirely: verifying the indeterminate verdict, the first injected throw sat outside the `try`, so the script crashed and exited 1 — which looked like proof and was not. Assert the thing only that handler produces (the verdict string, the named cause, the specific message), and enforcement changes to the harness itself get mutation-verified in BOTH directions: broken shows broken, restored shows ok.
  - **A derived document is a new input species for the HARNESS too.** Accumulation pluralizes selectors that generation 1 kept singular — one move row becomes two — so harness selectors get the producer sweep like any other consumer of a shape that changed.
  - **A geometry reading on an ANIMATED element measures the animation.** A box captured while a transition is running reports the position the element is LEAVING, and the number looks exactly like a layout fact. Receipt: the Mintlify refusal toast measured y≈695→807 against a 720px viewport, and the short card-creation toast measured 696→754 — a control group that appeared to CONFIRM an app-wide clipping bug. Both were mid-flight; settled, the same toast measures 585→697, wholly inside. The tell was in the screenshot that finally exposed it — a half-transparent element, which in a paint check usually means in-flight rather than faded. Wait for the box to stop moving, then read it; and treat a control group that agrees too neatly as a shared artifact until it is settled too.
  - **Logs state what was measured, from the measurement's own variables.** A parallel narration drifts: the gen-2 log recomputed "the first row of the source card" and named a row the probe had rejected, reporting the opposite of what it measured. Capture at the decision point and log that.
- **AN INSTRUMENT LEFT REGISTERED OUTLIVES ITS RUN, AND THE NEXT PERSON READS IT AS A PRODUCT DEFECT.** A forced-failure receipt was collected by registering a Playwright `page.route` against `api.anthropic.com/**` on a long-lived browser page, and the route was never removed. The next live attempt got the canned fixture back and it was indistinguishable from a real model failure — a plausible rejected proposal, the right byte count, the app behaving correctly on top of a lie. Three things make this class nasty: the glob matched EVERY path and method, so a GET to `/models` came back as a chat-completion object; the residue is invisible because it lives in the DRIVER's process, not the page, where no assertion inside the repo can see it; and the fake failure was _plausible_, so it consumed a real person's key-bearing run before anyone doubted it. **Rules: a forced-failure receipt drives a REAL endpoint rather than patching the browser** (`scripts/mock-provider.ts` — the residue of a finished run is a killed process, which is a state you can see); **every receipt carries per-request PROVENANCE** (a `cf-ray`, an Anthropic `request_id`, a round-trip time — values a fixture would have to forge and vary); and **a receipt attests the instrument's state as well as the measurement** — native `fetch`, a server-generated request id — both before it starts and after it ends. **A browser that outlives the test is a SHARED INSTRUMENT, not a scratch surface.** `src/ai/__tests__/noInterception.test.ts` fences the shipped app and says plainly, at the top, that it CANNOT see a driver-side route — which is the gap that caused this.
- **SUSPICIOUS SPEED IS A VACUITY SMELL — time the instrument, not just its verdict.** A check that passes far faster than the work it claims to have done has usually not done it, and nothing in a green run says so. Receipt: the godot corpus paint passed in 3.9 seconds for a 1,594-document import, which was in fact real — but asking why produced the scale assertion the check had been missing, and that assertion then caught a second defect (it compared the SECTION count against 400 and went red, looking like the guard working while measuring the wrong quantity). Both directions are the lesson: an implausible duration earns a look, and the assertion added in response needs its own units checked.
- **A DEMANDED RECEIPT KEEPS FINDING WHAT THE BUILD DID NOT.** Not one of the eight defects in the docs/19 build came from the unit suite; several came from receipts requested at review — "re-measure the kernel row", "state the .md keying", "verify the quadruple". Each was framed as bookkeeping and each surfaced something live: the parse row proved the tab fix was write-side only, the .md question exposed a suffix lookup that resolved no markdown document at all, and arithmetic on a published quadruple caught an ordering that made one corpus impossible. **Asking for a number in a form somebody can check is a defect detector**, which is the reason to publish measurements in tables with stated units and a stated ORDER rather than in prose.
- **An instrument that ACCEPTS is not an instrument that CHECKS — name what it does not enforce.** A tool's success is evidence only about the property that tool inspects, and the gap is invisible because the run is green. Receipt: neither `git apply` NOR GNU `patch` enforces a hunk's start line — both search by context and accept a header off by one without a murmur, so an apply-based oracle FALSE-PASSES on wrong numbering. Correct offsets therefore need a unit assertion; the receipt script cannot stand in for one. Same family as the oracle/probe split — an oracle's default is "that looks right" — and the working form is a ledger: for each instrument, write down what its green means and what it says nothing about.
- **A surprising mutation result gets a direct re-run before it is believed** — kills as much as survivals. A batch harness reported a load-bearing guard's mutant KILLED; re-run alone, it survived. A false KILL is the more dangerous direction, because it certifies coverage that is not there and nothing ever contradicts it, whereas a false survival merely sends you looking. Receipt: `targetIn`'s absolute-form fallback, which has no reachable producer at all — recorded as a surviving mutant with a property test asserting the claim it defends, rather than deleted or left looking covered.
- **Occlusion probes answer for hit-test PARTICIPANTS only.** `elementFromPoint` can never return an element the pointer passes through, so probing anything `pointer-events: none` — a drag ghost, an overlay, a decorative layer — reports "occluded" for something plainly on screen. The technique answers _is something on top of this?_, not _is this visible?_. For non-participants the alternate oracle is rendered-ness (non-zero box + `visibility` + `display` + `opacity`), and the probe should REPORT which oracle it used, so a green result cannot quietly mean the weaker check ran.
- **Grab content anchors, not centres.** A row's centre is empty trailing space that rubber-bands instead of dragging; the title is the handle. Centre-grabs produce a selection box and no gesture at all, which reads as a feature that does not work.
- **Re-query geometry after any layout- OR SCROLL-mutating action.** A bounding box captured before a drag, a delete, an expand or a re-pack points at whatever slid into those coordinates afterwards — so the next interaction hits the WRONG element and the failure arrives as a wrong message, a wrong count, a wrong refusal. That reads as a product bug and gets diagnosed as one. Receipt: the docs/16 reparent spec captured three row boxes up front, and after the first move the collision drag grabbed the bundle row and reported the bundle refusal. Capture boxes immediately before each use, never in a batch at the top. **Scrolling counts**: the corpus paint check's focus sweep pans to sixty rows and leaves the viewport at the last, after which every previously-captured box sits outside it and `elementFromPoint` returns null — nothing about the DOM changed and every coordinate was still wrong.
- **Absence assertions fast-fail.** Where absence is a legitimate ANSWER — an unmeasured count, an adapter with no harvester — a default 30s wait turns "correctly absent" into a stall, and a harness that takes a minute to report nothing is one nobody runs. Short timeouts on the assertions whose expected result is nothing.
- **No API keys in unattended harnesses**, standing rule. A check that needs a live provider is a check that cannot run in CI, cannot run on a fresh clone, and leaks a secret into a script somebody will paste. Where a second generation genuinely needs model output, replay a CANNED PROPOSAL through the same validate → reconstruct path instead; it is keyless, deterministic, and exercises everything after the network call. Until that fixture exists, such a check skips WITH ITS REASON rather than being quietly dropped.

Toolchain: Node ≥ 22, pnpm ≥ 10 (this machine: Homebrew node 26 / pnpm 11; non-login shells may need `eval "$(/opt/homebrew/bin/brew shellenv zsh)"`). pnpm settings (`allowBuilds`, overrides) live in `pnpm-workspace.yaml` — pnpm 10+ ignores a `"pnpm"` key in package.json; don't add one.

## Architecture

React 19 + TypeScript strict + Zustand/Immer + Tailwind 4 + Vite. Import alias `@/` → `src/`. Vite's `base: "./"` emits relative asset paths so the build works at any GitHub Pages subpath — don't "clean it up" to `/`. The design docs `docs/01`–`22` are the rationale record (03 architecture, 10 AI reorganize, 11 collection adapters, 12 Sphinx, 13 Mintlify, 14 Hugo, 15 snapshot ownership, 16 reparenting, 17 document summary, 19 Sphinx write-back, **21 aspirational moves — BUILT WHOLE, both arcs: the model path, the write path and the HAND**; 09 is retired — never renumbered, never reused). One is not built. `docs/18` (section reparenting — directory moves) is a different KIND of note again: a **DECISION RECORD, deferred with its charter parked**, not a design awaiting a build. Read it before costing anything in that area — the measurement says the gesture is two orders of magnitude rarer than docs/16's (six in-TOC directory reparents in eight years, none since 2019), and it names the two unlock conditions. Its survey is `scripts/survey-reparent.ts`; its save-path receipt is `scripts/receipt-move-patch.sh`. docs/18's survey is `scripts/survey-unread.ts`.

Layers, in dependency order:

- **`src/model/`** — the neutral, format-agnostic tree everything operates on: `TocDocument` → `Section[]` → `Topic[]` (`types.ts`). Stable string ids on sections **and** topics; nothing addresses nodes by array index (index addressing was the deepest bug source in prototyping). No stored derived data — depth, counts, palette are selectors (`selectors.ts`, `palette.ts`); serialization is on demand. Opaque `extras` bags carry format-private data the core clones but never interprets. Childless top-level entries are wrapped as orphan sections (`isOrphan`, entry at `topics[0]`).
- **`src/formats/`** — `TocFormatAdapter` for single-file formats (DocFX `toc.yml`, MkDocs `nav:`, Mintlify `docs.json`). The law is per-format round-trip: an unchanged document exports byte-stable (fixpoint), an edit touches only what changed. Cross-format conversion is a non-goal; there is no universal schema. Mintlify clears a higher bar than the law requires — **byte identity with the input**, including indent unit, trailing newline, EOL style and byte-order mark — because JSON has no comments to lose; it is also the first producer of `Section.chain` (navigation containers above the card, rebuilt via `partitionByChain`) and `Section.sealed`, and the first adapter to declare a per-kind `supportsRename` (docs/13). Being their first producer is what finished those mechanisms: they read as shipped for weeks and lost four facts on contact — docs/13's **Decided ≠ built** is the receipt, and the rule it leaves behind is that a mechanism with no producer is staged, not shipped.
- **`src/collections/`** — `CollectionAdapter` for folder-based systems (Just the Docs frontmatter, Docusaurus autogenerated sidebars). `parse(files)` stows the snapshot in `doc.extras.files` so `planChanges()` is pure; plans are minimal per-file edits, verified by simulation before save (at runtime and in tests); files are never deleted. Write-back: File System Access (Chromium) or `.patch` download. A collection document stores the **collection id as its `formatId`**, so every path that routes through the FORMAT registry (per-card code view, legacy export) needs an adapter answering to that id — the facades at the bottom of `collections/registry.ts` provide it.
  - **The snapshot owns the nav, not the file** (docs/15, `navHead.ts`). Pages are kept as **nav heads** — byte 0 through the closing front-matter fence, _excluding its line terminator_, because a head must never claim diff context it did not read (get that wrong and `git apply` refuses 41% of a real corpus). Config files that ARE the nav stay whole. Changes carry `region: "navHead"`; save splices into the bytes on disk **at save time**, so a body edited after load survives by construction — there is no drift guard and none is wanted. The snapshot is what the app loaded or last wrote, **never a disk mirror**: refresh splices in memory, since re-reading would quietly absorb a concurrent edit into the baseline. Concurrency is version control's job, with receipts (`scripts/receipt-vcs-merge.sh`).
  - Consequently the kept set is small: kubernetes/website is 445 KB across 1,672 pages instead of 14.79 MB. **`MAX_FILES` is gone** — removed, not resized, because `git log -S` showed it was `MAX_TOTAL_BYTES` counted twice with no per-entry cost ever measured. Don't reintroduce a kept-set count cap without a measurement.
- **`src/commands/`** — every mutation is a command executed through Immer `produceWithPatches`; undo/redo are derived inverse patches, never hand-written. Load-bearing invariant (fast-check): any command sequence, fully undone, restores byte-identical export. `execute.ts` is the ONLY place that touches the draft; `dispatcher.ts` wraps it and derives the undo label. A new command therefore lands in exactly three files — the `Command` union (`types.ts`), a case in `execute.ts`, a case in `labelFor` (`dispatcher.ts`) — and all three switches are exhaustive, so `pnpm check` names whatever you missed.
- **`src/store/`** — Zustand slices; versioned, debounced localStorage persistence, quota-guarded (`persistence.ts`). The main store owns tabs, editor state, and undo stacks only: **transient or high-frequency state lives in its own small store** rather than causing re-render storms here — `interaction/dragStore.ts`, `view/uiStore.ts`, `view/canvas/canvasSize.ts`, `animation/ghosts.ts`, `ai/settings.ts`. Put new ephemeral state in one of those, not in the main store.
- **`src/layout/`, `src/view/`, `src/interaction/`, `src/animation/`** — column layout → canvas/cards/connectors/minimap. All drags run through one `startDragGesture` utility; transient drag state lives in a separate `dragStore`; drop resolution = DOM data attributes + pure math (`dropMath.ts`). FLIP animation driven by command hints. Gotcha: canvas overlays must `stopPropagation` on pointerdown or the canvas pan pointer-capture eats their clicks.
- **`src/ai/`** — AI reorganize pipeline (next section).

**Shape-fidelity law — the axiom behind the caps regime** (PRODUCT.md principle 6): a limit may cost DETAIL, never SHAPE. Storage caps, render depth and payload bounds may reduce what is shown about a node; none may silently drop a branch or fold a subtree away. A truncated detail leaves the reader with less, a truncated shape leaves them confidently wrong. When a budget genuinely cannot be met, refuse and say why. This is why a collection loads its whole tree by default rather than a convenient subtree, and why `MAX_FILES` was removed rather than worked around.

Two verified policies — do not regress:

- **Pan bound is strictly the content origin** (x ≤ 0, y ≤ 0 in screen px — zoom-independent), rubber-band + snap-back on drag, hard clamp on wheel-pan and after zoom; fit-to-view anchors **top-left**. Do not reintroduce a "relaxed/centered" bound — it scales with zoom and opens blank space top-left.
- **Visual language is pinned** in docs/05 ("Visual language": 8px card radius, 2.5px dashed borders, 12-hue palette, grey orphans). Copy those values; don't restyle or let a library default override them. One scoped dated amendment (2026-08-18): header INK — card title, count pill, card glyph — derives from the darker per-hue ramp in `view/canvas/badgeColors.ts`, not the palette's `text` column, because five `text` shades measure 3.1–4.4:1 on their own tints; the palette table itself stays verbatim for everything else.

## AI reorganize (shipped — docs/10)

"Reorganize with AI" is built and verified against live Gemini. As-built decisions (these supersede earlier planning notes where they differ):

- **Tokenized topics**: each node gets a compact stable id (`s1` = section, `t1` = topic); the id→object map stays in the browser. **Titles only** are sent — paths, UUIDs, and `extras` never leave. Optional folder hints add directory prefixes (never file names).
- **Indented-text outline in AND out** — deliberately chosen over JSON structured output (≈2–4× fewer tokens; output limits are the binding constraint on large TOCs). Parsing (`parse.ts`) is layered-tolerant — fences, prose, bullets, ragged indents, JSON fallback — but identity-strict. Known residual: indent drift can silently misnest a proposal (content-safety still guaranteed by the multiset net); the planned fix is per-provider JSON structured output — see Roadmap.
- **Prompt separation** (`prompt.ts`): the fixed system message owns the format contract (id rules, children-follow, scope read-only); the user-editable instruction is ONLY the optimization goal. Presets (Balance / Flatten / Reader journey / Diátaxis) are editable instruction templates, not code — no separate "Custom".
- **Renames and new groups are explicit syntax**, gated by options: `t3 ~ New Title` (allowRenames), `+ Title` (allowNewSections).
- **Validate before anything opens** (`validate.ts`): unknown/duplicate ids → one guided retry with specific errors → clean failure. Reconstruction rebuilds from the ORIGINAL objects by id; children-follow keeps unlisted subtrees; omitted topics are recovered into their original sections; a fast-check-tested **topic-id multiset invariant** refuses any result that drops or duplicates topics. An invalid result is never shown.
- **Results open as a new tab only** — named `"<source tab> (<model>)"` since the streaming amendment (the differential workflow is two runs of one document side by side, and the old `"(reorganized)"` was two identical labels for the two things being compared), `formatId` preserved, the original never touched; the user compares tabs, and closing the tab is the reject gesture. (A real diff view between tabs is backlog; its FEED — tab provenance — now exists.)
- **Provider abstraction** (`providers.ts` + `client.ts`): thin OpenAI-compatible client. Presets: Gemini Flash free tier (default model `gemini-flash-latest` — the alias survives Google's renames; never hard-pin `gemini-2.5-flash`, it was retired server-side), **Claude via Anthropic's OpenAI-compatibility layer** (see the dated line below), and a custom base-URL escape hatch; Groq/OpenRouter/Mistral are future preset entries. BYO API key, in-memory unless "remember on this device" (localStorage, with forget affordance). Settings persist even when the key doesn't — stale stored model names survive app updates. The dialog states exactly what is sent (titles only), and the training disclosure ships as required `ProviderPreset.trainingNote` — per-preset claims at verified strength with sources and retrieval dates at the field declaration (Gemini free tier trains; Anthropic API does not by default, attributed; custom is conditional), rendered by the key field in SettingsView (release-prep, 2026-08-27; claim directions pinned by `trainingNote.test.ts`, render hit-tested in flow 8).
- **Provider extra headers + Claude preset + rejected-response capture (docs/10 amendment, 2026-08-18):** `ProviderPreset.extraHeaders` is a TRANSPORT seam — neither an instruction nor a permission, the two things presets already regulate — merged into BOTH client calls (chat and model-list; wiring only the first leaves "Fetch available models" CORS-failing for the one provider that needs it). Its producer is the Claude preset (`https://api.anthropic.com/v1/`, `claude-opus-5`), which cannot reach the browser without `anthropic-dangerous-direct-browser-access: true`: **measured**, a preflight without it answers `400 Disallowed CORS origin` with no `access-control-allow-origin`, and a browser fetch without it throws `TypeError` while one with it returns a plain `401` — so an auth error rather than a CORS failure IS the keyless receipt that the seam works. Settings copy is honest by obligation (dev/testing, paid-only) and that flip forced a copy sweep onto `keyLabel`, since "Get a free key" was true of Gemini and a lie about Anthropic. **Single producer, pre-declared:** the mechanism is staged not proved until OpenRouter's attribution headers land, chosen for being different in KIND. **Two live 400s on 2026-08-19 added two more per-preset facts, both data-shaped like the header:** `supportsTemperature: false` (the provider answered "temperature is deprecated for this model" — the KEY is omitted, not neutralised, and Gemini's payload is asserted unchanged) and `supportsModelList: false` (a VALID funded key was refused exactly as a dummy one was, **falsifying an inference this build had recorded as an inference** — a keyless matrix shows `Bearer` → "Invalid bearer token" vs `x-api-key` → "API key is invalid.", i.e. two credential TYPES, so no key of ours could ever have worked; the button is disabled through the disabled-with-a-reason seam, and native per-endpoint auth is recorded as the road not taken rather than built as a second single-producer seam). **API keys are PER PROVIDER** (`apiKeys` map + `currentKey()`), because one shared field posted the previous provider's funded key to the next provider's endpoint on the run after a switch — and the differential workflow IS that switching pattern. Structural, not vigilance: key and base URL derive from the same `providerId`, so they cannot disagree; a legacy single key is deliberately NOT migrated (attributing it means trusting the very field that carried keys across providers); custom gets one slot keyed by preset id, since switching presets changes a destination the user cannot see while editing a custom URL shows both at once. A rejected proposal now keeps its RAW BYTES on the thrown `AiError` (`capture.ts`) with `stage` and `attempt` as two fields, never one "phase" — a proposal can parse only on the retry and still be refused by reconstruction. Two deliberate absences: no copy button on a transport failure (no model output to promise), and a retry-rescued parse failure reaches only the DEV log.
- **Streaming, a live log, cancel, and tab provenance (docs/10 amendment, 2026-08-19):** the call carries `stream: true` and accumulates SSE deltas; what the client RETURNS is unchanged, so parse/validate/reconstruct are untouched by construction and the payload diff is asserted as a DIFF, not a shape. **Three end states, not two** (`sawDone` / `finishReason` / `providerError`; none set = abrupt close, its own answer). **The fallback is a CLASSIFIER with both sides asserted**: a 200 that is not `text/event-stream` is READ rather than re-requested, a **400** is retried once with the key REMOVED (the only status that can complain about the request body), and 401/429/5xx/throw are excluded — mutating the predicate to `!response.ok` kills three of those four tests. A broken stream now keeps its bytes: `AiError.partial` becomes a capture at a **third stage, `stream`**, which **reverses the earlier "truncation carries no capture" ruling and reconciles rather than overrules it** — the objection (a fragment read as a proposal) was right while `stage` could only say parse or validate, and the new value is what answers it. The dialog's stage copy became a `Record<CaptureStage, string>` so a fourth stage cannot ship unlabelled. **Cancel populates NO capture, and the guard is not vacuous**: the client attaches partial bytes to an aborted call exactly as to a broken one, so `run.ts` declines something real. **The log is a claim** — the sent block is rendered FROM the posted bytes, never assembled a second time from the same intent; `call` and `request` are two events because one call makes two requests on a fallback and one run makes two calls on a retry; the retry marker is STRUCTURAL. `waiting for the first token` is its own state, and **thinking content is a recorded ABSENCE** (the compat layer streams none). ## Conventions

- Every module opens with a `/** filename.ts — purpose */` docblock explaining its role; keep that.
- New format/system support = one adapter file in `src/formats/adapters/` or `src/collections/adapters/` + fixtures + one registry line, validated by the shared conformance suite / round-trip property test. CONTRIBUTING.md is the authoritative adapter guide. (A _collection_ adapter also has to work through the format-registry facade path described above — the one-line promise covers registration, not that.)
- Invariants get fast-check property tests, not example tests.
- **Test-writing friction is a design instrument**, the sibling of mutation-checking. A mutant that survives says the tests are thin; a test that is unreasonably hard to WRITE says the design is wrong, and it says so before the defect ships. The tell is a fixture you cannot construct honestly — needing to reach past the API, pin an ordering, or arrange the world so the code happens to be right. Receipt: the docs/16 alias check kept one holder per URL in a `Map`, so a permalink-collision fixture could not be written without depending on iteration order — and the only case the check exists for has TWO holders (a `slug:` makes two pages publish at one URL, and after one moves away the other legitimately owns it). Collapsing the duplicates hid exactly the case being checked. The map became a multimap because the test was awkward, not because a test failed. **When a test is hard to write, suspect the code before the test.**
- **Published-rendering fidelity.** Any claim an adapter makes about what a documentation system _renders_ — visibility, ordering, whether a page appears at all — needs a receipt from the theme's template or the live site, cited in the code. A front-matter key that reads like a visibility flag frequently is not: Hugo's `no_list` styles a landing page's child list and the sidebar never consults it, and deriving a "hidden" mark from its name mislabelled 77 of 1,038 corpus pages. Fixtures cannot catch this class — the fixture encodes the same wrong belief and goes green, which is what happened. Check the rendered site.
- **A MEASUREMENT is not the BYTES that produced it, and storing the measurement loses the difference.** The two read identically until something has to write the value back. Two receipts from one build: an indent WIDTH cannot say whether column 8 was a tab, eight spaces, or two spaces and a tab, so `" ".repeat(n)` rewrote `\tentry` as `" entry"`; and a separator stored as a BOOLEAN cannot say how many blank lines there were, so a double blank came back single. **A boolean is a count of one** — the degenerate case of the same error. Where a value will be re-emitted, keep the bytes and derive the measurement, never the reverse; split them into two fields with two names when both are wanted (`contentIndent` / `contentPrefix`).
- **LOOKUP and WRITE are two questions about the same name — do not answer them with one function.** Where a thing can be spelled several ways but is created with one, "where is it?" and "where would it go?" diverge, and a single function silently answers the second while callers ask the first. Receipt: `docPath` used `source_suffix`'s FIRST entry for both, so a Sphinx project declaring `[".rst", ".md"]` could not resolve a single markdown document — every one became a `missing` placeholder, populated and confident and wrong. Split into `findDoc` (tries each declared suffix, as Sphinx does) and `docPath` (writes the first). Same family as `routeOf`/`docIdOf`: the pair that looks redundant is the pair this project pays for.
- **DEFERRED and DESIGNED ABSENCE are different rulings, and calling one the other misleads in opposite directions.** Deferred means the need exists and the work does not — it implies a gap someone should close, and it belongs in a backlog with an unlock condition. Receipt: this line ships alongside the correction of exactly that — `docs/12` read "no `src/` code, no registry entry" while `sphinx.ts` sat in the registry, `docs/14` read "design only" against a shipped adapter, and `docs/17` read "gated" the day it was certified. **Landing a doc's build is not done until the index says so.**
  - The whole rule in order: **investigate before amending, sweep after.** Order of operations is load-bearing at both ends.
- Prettier ignores `docs/` and README (user-authored prose) and test fixtures (also git `-text` — a format pass once silently LF-normalized a CRLF fixture). Don't format them.
- Commit subjects: short declarative "Area: what changed" (see `git log`).
- The working tree is multi-session: another session can switch the checked-out branch mid-run. Run `git branch --show-current` immediately before every commit, not just at branch creation. If commits land on the wrong branch, cherry-pick onto the intended branch rather than resetting the other one, and flag the entanglement at the top of the report. ## Design and build arcs

How work ships here. An arc is one chartered task given to one fresh instance: design arcs produce or revise a docs note; build arcs produce code under a certified note.

- All work happens on a branch named in the report. Main moves only on Roger's explicit merge instruction after certification — never on acceptance of a draft. Commits already on main = automatic REVISE.
- Verdicts are ACCEPT / REVISE / NEEDS-HUMAN from the adjudicator; Roger holds every gate. A note ships as DRAFT with its open rulings
  listed; it becomes canon only on his certification, never by self-certification. Ruled items convert to dated rulings records in
  the note.
- Reports state BOTH SHAs — local and origin — and carry a self-check mapping each charter directive to where it landed.
- A scoped REVISE round's diff reads as exactly the named fixes — no drive-by improvements. Rounds are typically one squashed commit (a default, not law; the charter's budget governs).
- If a directed fix collides with the code, STOP and report the collision; never design around it — unless the resolution is uniquely determined by cited canon, in which case proceed and flag it at the top of the report for adjudication. Verify a handoff's factual premises against the code before building on them, and name any disagreement in the report even when the directed edit still stands.
- Test ownership (ruled 2026-08-19): the design note names every contract test — what is asserted, in what form, against what oracle; never test code in a note. The builder writes all test code, plus its own workmanship tests and one named regression test per defect found. Build reports map each named fence → test file → the actual assertion; adjudication reads the assertions, not the map.
- Commit ids cited in the design notes predate the public history and resolve only in the private working repo; sweeping them would falsify certified records.
- Instance memory (ruled 2026-08-19): the Claude Code project memory directory is for private working notes and pointers to repo artifacts — never a publication channel. Process and design claims land in the repo through the gate, or in the report, or they don't land. Where loaded memory conflicts with a charter, THE CHARTER GOVERNS; note the difference in the report rather than obeying it.
